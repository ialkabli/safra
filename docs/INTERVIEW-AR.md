# كيف أشرح مشروع سَفرة؟

## تعريف مختصر

«بنيت مشروعًا تجريبيًا لتطبيق أندرويد عربي لـحجز السفر، بهدف عرض تدفق استخدام كامل وحفظ محلي وقواعد تحقق، وليس مجرد شاشات ثابتة.»

## ماذا يفعل؟

سعة المقاعد لكل رحلة ويوم، وحفظ إجمالي السعر بالهللة، وإعادة المقاعد عند الإلغاء.

## قرارات تقنية أستطيع شرحها

SQLite transaction للحجز الذري؛ مفتاح محاولة يمنع تكرار الحجز؛ السعر محفوظ وقت الحجز.

اخترت Java وواجهات أندرويد الأصلية وقاعدة SQLite لتكون النسخة مستقلة وصغيرة، دون خدمات سحابية. يفصل Store قواعد البيانات عن العرض، وRules تحققًا يمكن اختباره دون جهاز. تُنفذ عمليات التخزين في executor واحد لكل نافذة، مع المعاملات عند الحاجة للتنسيق بين النوافذ.

## إذا سألوا هل هو مشروع حقيقي منشور؟

«هو مشروع شخصي تجريبي لمعرض أعمالي، وليس عقدًا مع شركة. استخدمت مساعدة ذكاء اصطناعي أثناء الإعداد، وأراجع الشيفرة وأتعلم شرح قراراتها. حالة الاختبارات موثقة بدقة في ملفات المشروع.»

## ما الذي يحتاجه قبل استخدام حقيقي؟

فهرس رحلات ذهاب تجريبية بين الرياض وجدة وأبها. لا تذاكر أو دفع أو بحث لدى شركات طيران.

للخدمة متعددة المستخدمين نحتاج خادمًا مسؤولًا عن التوفر، وهوية المستخدم، وصلاحياته ومراقبة الأعطال، واختبارات على أجهزة فعلية. لا أقدّم الحفظ المحلي على أنه حجز لدى مزود خارجي.

## عرض عملي

ابدأ بالصفحة الرئيسية؛ أضف سجلًا صحيحًا؛ جرّب إدخالًا مرفوضًا واشرح السبب؛ افتح السجل بعد إعادة تشغيل التطبيق؛ ثم جرّب الإلغاء أو الإنجاز. اقرأ اختبارات Store قبل شرح المعاملات أو التزامن.
